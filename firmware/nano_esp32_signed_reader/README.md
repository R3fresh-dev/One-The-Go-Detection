# Signed physical research reader

This protocol adapter supports approved external instruments and includes an opt-in real ESP32-S3 ADC acquisition driver for cardiac PPG and ECG. It never substitutes simulator fixtures or creates a device key on the phone. The simulator is a separate firmware target.

The stock Nano board package compiles this reader but cannot supply protected NVS: the application refuses to advertise without actual secure boot, flash encryption, encrypted identity NVS, a provisioned P256 identity and a provisioned server grant public key. Use the separate [security-enabled SDK entry](../secure_reader/README.md) to build that branch. Compilation does not establish electrical safety, instrument accuracy, key provisioning or physical qualification.

## Device/server binding and capture

BLE service/characteristic UUIDs and byte framing match the existing documented transport. The reader advertises `source=prototype_sensor` and `protocol_id=otgd_signed_reader_v1`. An approved reader remains distinct from a validated assay or model.

The application forwards the exact server binding transcript to the device. The protected device key signs `OTGD-BIND-v1\n` plus RFC8785 JCS. The server verifies its independently approved public key and issues the binding receipt. The phone then obtains a fresh, one-use 32-byte device nonce and submits it, the physical boot ID and its current owned attempt to the server's start endpoint.

The server returns `server_start={grant,signature,key_id,domain}`. The domain is `OTGD capture grant v1` followed by one NUL byte (22 bytes total). The signature is ASN.1 DER ECDSA P256/SHA256 encoded as base64. The grant binds environment, owner, data generation, session/attempt/authorization/binding/device/key/boot, scientific configuration hash, complete submitted configuration hash/version, frozen capture-context hash, channel, maximum duration, signed raw permission, issue/expiry timestamps, device nonce and server nonce. The phone forwards canonical token bytes as base64 so the NUL never enters ordinary transport JSON values.

The reader verifies against its protected, provisioned server SPKI and signer label; a token cannot provide its own trusted key. It compares all hardware/session/options fields and admits a fresh nonce only once. Strict UTC issue/expiry arithmetic must give a positive lifetime no longer than 60 seconds. The device nonce age must be strictly shorter than that signed lifetime, conservatively accounting for the time before the server signature without inventing a device wall clock.

Results are signed by the device over `OTGD-CAPTURE-v1\n` plus the JCS envelope. The envelope binds current scope, boot, sequence, configuration and SHA256 of the exact normalized projection. A phone digest/DER check is structural admission only; the server verifies cryptography and current registry authority before retention/eligibility. Feature-only captures do not retain or persist provisional sample chunks, and the client rejects unsolicited raw chunks before retaining a ledger. Cancellation and disconnect clear retained provisional chunks. Opt-in ECG recording requires a signed non-null record permission plus approved protected `raw_sample_limit` in 1..1024, `raw_encoding=otgd_ecg_samples_v1` and a complete configured sample budget that fits that limit. Unsupported raw requests are refused before acquisition. Actual observations remain in bounded RAM until acquisition stops; each unchanged chunk contains at most 64 samples and separately signed exact payload SHA256. Chunk metadata includes measured acquisition start/end microseconds, sample rate, uV units, contact, first index and explicit gaps. The phone handoff `OTGD-ECG-SAMPLES-v1\n` plus canonical JCS retains the exact final attestation and signed chunks, with a maximum 256KiB byte envelope, SHA256 and immutable dimensions. There is no phone signing or automatic upload. Server verification against the approved device key remains authoritative.

## Authenticated encrypted BLE

A protected unique six-digit `reader/ble_passkey` is provisioned offline and displayed on a controlled physical device label. There is no default passkey, serial disclosure, Just Works fallback or unattended numeric confirmation. The OS pairing dialog requires that label. The device requires BLE LE Secure Connections with MITM bonding and a 16-byte negotiated key, and uses encrypted-MITM permissions for capabilities, commands and the notification CCCD. Command/notification admission additionally requires the actual current peer address, connection ID and authentication callback; the stack is configured to accept only the specified authentication mode; three failures block new links until an operator restart. Missing protected material prevents advertising. Bond material is stored under the security-enabled encrypted NVS SDK.

The pinned stack reports authentication completion with a peer address rather than an originating connection generation. Source fencing rejects foreign peers and downgraded authentication, but same-address disconnect/reconnect callback ordering, bond resumption, OS passkey handling and confidentiality require the physical stack failure matrix. These host tests do not prove every stale same-address callback impossible. Physical label custody, per-device passkey uniqueness, removal of stale bonds and controlled re-pairing are manufacturing/operator prerequisites.

## Actual ADC acquisition

Offline encrypted NVS `reader/adc_provision` contains strict JSON `{schema_version,configuration_id,configuration_hash,configuration_submitted_sha256,configuration_version,calibration_id,material}`. `material` matches the operator's approved `ADCMaterial`: schema/protocol/adapter/channel/modality, duration, end guard, sample rate/unit/extractor, input and independent contact GPIOs, contact polarity, 12-bit resolution/11dB attenuation, independently approved reference/gain/offset, peak threshold, admitted interval bounds, minimum amplitude and exact raw capacity/encoding. No GPIO, gain, physiology value or configuration identity has a default.

Only ESP32-S3 ADC1 GPIO1–10 is admitted; contact uses the operator schema's separate safe GPIO allowlist. The Nano core's actual Arduino pin remapping is resolved before calls. The driver uses real `analogRead`, real `digitalRead` contact and `esp_timer_get_time` observations. An absent contact stops acquisition and cannot produce valid features. Floating/noisy/saturated inputs, missed samples, insufficient amplitude/intervals and clock overrun produce invalid evidence. ECG microvolt conversion requires the exact protected reference, offset and amplifier gain pinned by the approved calibration/configuration. No chemical measurement is inferred from an ADC or an MQ sensor.

The bounded extractor `adc_peak_intervals_v1` derives heart rate and optional RMSSD from observed threshold-crossing intervals; it is a software implementation requiring independent physiological qualification. It retains aggregate intervals (maximum512) and bounded optional raw RAM (at most 1024 observations, pinned by configuration). The feature-only branch never enqueues raw samples. Each loop advances acquisition before inspecting transmit congestion. The configured 10–100ms end guard stops actual reads before the signed strict duration, and driver shutdown never waits on an acknowledgment or network request.

Absolute projection timestamps use the signed server issue timestamp as an expressly unqualified wall anchor plus actual observed acquisition duration. `SERVER_WALL_ANCHOR_UNQUALIFIED` and `ADC_PEAK_INTERVALS_V1` are retained; no frame-accurate, synchronized or clinically qualified wall-clock claim is made. Measured device monotonic completion anchors are carried by the transport; raw chunk start/end anchors are independently included in their signed payloads. The final scientific projection alone does not cryptographically bind transport timing metadata. Model eligibility remains independently controlled and requires the outstanding physical/calibration/timing evidence.

## Bounds, connection isolation and checks

The transport retains128 immutable command tombstones,64KiB response cache,8 TX messages/32KiB,64 RX packets,8192-byte logical records and at most64 generic instrument chunks. Reconnection scrubs participant-bearing cached payloads and retains old-origin replay tombstones. A shared short origin mutex serializes connection transitions against all driver start/tick/stop hooks, device signing, RX insertion and notification. Notifications target only the authenticated connection ID; the SDK broadcast notify API is not used. Second simultaneous links are refused. Disconnect immediately stops the driver. Native client late-write failures are generation-fenced.

Build the actual Nano target with the existing pinned board toolchain. Portable checks are `signed_reader_core_test.cpp` (exact JCS, numeric precision, domain/bounds), `signed_reader_acquisition_test.cpp` (actual-used scheduler/extractor, no-contact/cutoff/drops/calibration, strict shortened expiry and threaded final-check connection transition) and the shared protocol byte/parser tests. These checks do not flash a board. Actual protected SDK compilation on 2026-10-11 produced application, bootloader and partition binaries; the generated manifest records exact source and artifact hashes. The final stock Nano compilation also passed (1,030,957 program bytes and 76,236 static RAM bytes). Both local compilations used the same frozen reader code. Fresh exact-source CI remains required before merge. Neither result flashes or qualifies a physical board.

External saliva/alcohol/chemical vendor acquisition remains unavailable unless a separately documented, approved strong `AcquisitionDriver` is linked. Transport decoding of signed compatible evidence does not implement an unknown assay SDK or qualify its results.
