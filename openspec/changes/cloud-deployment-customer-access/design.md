# Design

## Traceability and release limits

The PRD defines participant/operator research journeys and forbids consumer distribution claims before validation. HLD makes authenticated TLS, managed PostgreSQL, private objects and queues the AWS boundary; LLD requires immutable provenance and tenant access before storage. This delta makes deployment and customer browser access concrete without changing research authorization. Browser UI is the actual shared Expo application. Its storage/native adapters retain their documented browser limitations; a hosted browser does not become a native hardware implementation.

## Infrastructure and public identity

Each existing isolated AWS environment gains a retained, versioned, AES-256 S3 WebAssets bucket. BlockPublicAccess and TLS denial remain enabled; no S3 website endpoint exists. CloudFront uses SigV4 OAC and a bucket policy restricted to this distribution ARN. Its origin path is `releases/<reviewed commit>`. Read methods only, HTTPS redirect, security response headers and an extensionless viewer-request SPA rewrite apply. Missing JS/image/font files preserve origin error status.

Default access uses the distribution's HTTPS domain. Optional `webDomain` requires a same-account ACM certificate in us-east-1; an existing public zone can manage a subdomain CNAME. The regional API ACM certificate remains separate. Cognito callbacks/logout and backend CORS include the exact resulting web origin plus `/`, alongside native callbacks. No wildcard callback is introduced. CDK outputs contain only public identity/resource identifiers.

## Signed browser artifact

The web builder requires a clean reviewed checkout and successful live exact-revision release admission. It extracts `git archive` for that commit into an isolated temporary directory, installs the committed npm lock and builds Expo with fixed environment/API/issuer/public client from actual stack outputs. Existing host APP/EAS/EXPO_PUBLIC and NODE_OPTIONS values cannot override these inputs. npm/export subprocesses do not inherit AWS credentials/profiles, application secret configuration, service tokens or SSH-agent values; proxy/CA/npm transport configuration is retained. Signing and cloud publishing occur in separate parent stages. The committed source remains trusted and reviewed; environment filtering is not a filesystem sandbox for arbitrary malicious build code.

The ZIP has deterministic timestamps, bounded public asset types, no symlinks/source maps/secret files, at most 256 files, 16 MiB per file and 128 MiB total. A canonical RFC8785 manifest records exact relative paths, content types, sizes and SHA-256 values. The signed Ed25519 web release binds environment/account/region/source/image, service envelope hash, live gate hash, runtime configuration hash, package-lock hash, archive hash, manifest hash and immutable prefix. An independently trusted public key verifies it; an embedded key or local status file cannot authorize publication.

QA and production have the same reviewed application source/lock but distinct fixed public runtime identities, so their bundle bytes differ. The signed production web record additionally binds the signed tested QA web envelope. Production's existing signed QA approval must include `web_customer_access` in `passed_gates`, set `evidence_refs.web_customer_access` to `sha256:<QA web envelope hash>`, and separately reference actual authenticated browser acceptance results through `evidence_refs.web_customer_access_results` (protected HTTPS/S3). This is an explicit signed operator attestation after review of the retained report; scripts do not replay those tests or infer their execution from artifact hashes/public probes.

## One-command state machine

`deploy/qa.py` and `deploy/prod.py` call shared orchestration but reject the opposite environment. `--plan` validates configuration and lists stages without credentials, builds, signing, resource mutations or success receipts. Execution validates source/gate/signer, target STS account, certificates, regional RDS/cost inputs, then CDK bootstrap/registry. Cloud SDK clients ignore ambient/profile endpoints and reject explicit endpoint overrides; child commands remove endpoint environment variables and force configured-endpoint ignore so local emulation cannot replace cloud proofs or mutations. QA builds/signs an immutable service release unless one is supplied; production promotes the approved QA digest unless a correctly signed target release is supplied.

An existing service is drained; a missing stack is recognized only by the actual AWS absent-stack error. Infrastructure/security is deployed stopped. Journal continuity is verified (first empty environment requires explicit `--establish-new`), migrations execute in the private maintenance task, and recovery executes only with the actual reviewed backup point. After the signed web build, `verify-admission` runs the exact `uv run --no-sync python -m otgd.recovery_authority` command in that pinned maintenance task. It independently verifies actual journal/control Object Lock and pinned versions, accepted deletion/generation barriers and database activation binding even when recoveryRequired=false. Activation requires migration/recovery evidence plus this exact admission task's actual ECS completion within fifteen minutes, UTC receipt completion within sixty seconds, matching account/region/source/image and no unexpected overrides. Runtime separately enforces admission authority. Worker progress health must become HEALTHY within ten minutes. The web artifact is verified again against actual stack identity before upload. Dependencies upload first, index.html last, using create-if-absent plus actual downloaded-byte verification. CloudFront invalidation completion is bounded at fifteen minutes.

Each invocation uses a new ignored attempt directory. Existing signed records/receipts/releases are retained. A bounded private deployment-state.json journals actual stages before/after execution, hashes/paths of existing receipts, and failure stage/type. Only successful return records stage completion; failure prints the exact recovery path and never infers rollback. Same-prefix object conflicts fail; no forced overwrite erases a prior artifact. The final receipt reports public transport verification and actual worker health, separately recording authenticated customer acceptance as not executed and cloud operational acceptance as not inferred. A stage failure exits nonzero; no later success receipt is generated. Recovery/rollback requires the existing operational runbook and fresh admitted maintenance evidence.

## Customer access and DNS

After a successful command, the operator receives WebOrigin, release/artifact/maintenance paths and concrete public probes. Opening WebOrigin presents the actual app, notice and its environment identification. Sign-in uses exact Cognito callbacks and authenticated APIs; scoped study enrollment/consent remains necessary. Browser memory storage and native-device capture limitations are visible rather than silently emulated as real evidence.

`register_cname.py` defaults to a live-validated change preview. `--apply` performs one UPSERT and waits at most ten minutes. It accepts no arbitrary target: distribution/domain/release come from the exact admitted stack. It rejects apex, private/foreign zone, pending/wrong TLS, missing alias, unready/foreign distribution and an existing conflicting record. CDK-managed DNS is already idempotent; a separate operation supports explicitly selected public zones.

## Evidence boundaries

Unit tests cover admission, tampering, publication ordering, DNS rejection and stage failures. CDK tests inspect actual QA/prod synthesized policies/functions/callbacks. Public HTTPS byte/header/deep-link/missing-asset/API probes do not replace signed-in ATDD, AWS IAM/KMS/private network, worker interruption, deletion restore, alarm delivery, device or store evidence. No AWS account is currently supplied; live deployment and those probes remain open acceptance tasks.
