# Qualified participant collection and instruction journeys

## Why

The canonical application has executable approved task, optical and signed-reader foundations, but its reference-laboratory saliva capability routes the customer to a BLE reader rather than an approved collection form. The PPG/ECG start action also lacks the protocol-derived instruction and compliance journey specified by AND-HR-002 and AND-ECG-002. Generic ADC support does not implement the selected SparkFun SEN-15219 digital PPG breakout in the committed shopping list.

These are software omissions. Genuine methods, study consent, electrical/optical safety, calibration and model qualification remain independent external requirements. No fictional engineering fixture supplies those approvals for participant use.

## What Changes

- Add immutable approved participant instructions and bounded form/setup rules to the released configuration envelope, with exact current acknowledgment receipts before fresh starts.
- Implement an owned reference-lab specimen collection journey without BLE, preserve complete specimen/attempt metadata, and display pending analytical work without a fabricated value.
- Retain authorized staff import and immutable finalized report-revision boundaries; participants cannot self-attest laboratory analysis.
- Implement the selected MAX30101/MAX32664 PPG driver using an immutable official SparkFun SDK pin, fresh sensor data and original vendor-quality semantics.
- Keep participant declarations separate from actual hardware-state evidence and G-05. Unsupported human ECG power-state verification stays refused.
- Add an explicit restricted HR-only server interval authority for independently approved device behavior/calibration and model policy. Preserve original unqualified timing flags and snapshots; no precise sensor clock or clinical claim is introduced.
- Test positive journeys, stale/revoked/config-changed states, lost responses, cancellation, incomplete samples, fresh FIFO behavior and connection-origin isolation.

## Capabilities

### New Capabilities

- `participant-instruction-authority`: exact approved instruction presentation, acknowledgment and start binding.
- `reference-lab-collection`: protocol-derived specimen forms, original collection lineage, pending analysis and authorized handoff.
- `selected-vendor-ppg`: selected digital PPG initialization, measured acquisition, quality, signing and bounded lifecycle.
- `scoped-cardiac-authority`: exact independently released HR-only policy, conservative original server interval proof, baseline compatibility and current publication admission.

### Modified Capabilities

- `research-evaluation`: preserve EVAL-002's original four matched ablations and complete accounting while adding an explicit frozen, separately scoped HR-only report mode without invented comparisons.

The participant requirements complete positive branches of the unarchived production-mobile-platform baseline. They preserve its existing scientific, provenance, privacy and versioned research-result boundaries. Archive requires the original baseline and authorized-model-execution capabilities before this delta; no archive is performed here. The untracked historical BOARD-FIRMWARE draft is not a canonical requirement or archive target.

## Impact

Canonical operator configuration schemas, generated contracts, API participant receipts/collection routes, native Android/iOS customer UI and encrypted queue, selected reader driver/build pins, cross-language fixtures and required merge checks. The numerical acquisition material hash remains distinct from the full released configuration-envelope digest, which covers the instruction protocol. Changing the protocol requires a new independently approved configuration version.
