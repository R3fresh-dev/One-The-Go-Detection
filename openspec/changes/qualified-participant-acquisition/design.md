This change implements PRD-009–016/018/025, FULL_SPECIFICATION HW-003/007/012, ANA-001/003/012, APP-003/010, SEC-002–005 and OPS-002–005; HLD sections 4–5/8; and LLD sections 3–5/8–10. The selected PPG hardware is the committed [shopping list](../../../specs/SHOPPING_LIST.md) and [hardware guide](../../../specs/HARDWARE_STARTER_GUIDE.md), with LLD section 5.1's chosen-breakout quality rules. ## Configuration and presentation identity

The independently submitted/reviewed/released Configuration contains a typed participant protocol with bounded exact instruction text/version/hash, named required confirmations, permitted declared-context choices and optional collection-form rules. The configuration registry ID/version and full submitted RFC 8785 digest cover the protocol. They remain distinct from the numerical `material` scientific digest, including the frozen task configuration. Changing instruction text, required fields, collection method, setup scope or limits requires a new configuration version and matching qualification of its full submitted content.

The server supplies the exact current protocol for an owned draft/check and channel after the same account/generation, notice, study invitation/document, consent and configuration checks as acquisition. A public configuration flag or cached capability alone grants no authority. The client displays the exact bounded text as text, preserves its identity, and renders only named fields/types permitted by the protocol. It does not synthesize a universal collection, rest interval, blow duration, finger placement or electrode procedure. Missing protocol produces a concrete unavailable reason.

## Acknowledgment and fresh starts

The acknowledgment names the owned session, channel, configuration registry ID/version/full submitted digest, protocol digest, required confirmations, permitted declared context and explicit UTC acknowledgment time. The immutable server receipt derives account/generation, current consent receipt, study and actual acceptance time. A client cannot supply an approver, laboratory identity or observed safety assertion through this request. The client durably retains the exact request body/key before transmission and accepts only a matching receipt.

The protocol's `maximum_acknowledgment_age_seconds` is an integer from 1 through 300. Initial acknowledgment is no earlier than attempt creation minus five seconds, no more than the approved age before service time and at most five seconds in the future. At grant/start, age is measured from the earlier of the original client acknowledgment and original server acceptance; equality at the maximum is permitted and any greater age expires. An idempotent receipt never advances either original time. Expiry requires explicit new presentation and confirmation rather than silent retry-time rewriting.

Fresh start authority binds the receipt and re-admits current configuration/protocol/consent, independently qualified hardware and the frozen owned context. The server authorization pins the exact immutable instruction receipt ID/digest. Its existing signed authorization ID together with full configuration/context hashes may provide transitive receipt binding; firmware need not duplicate a receipt field if that authorization cannot change scope. One receipt cannot authorize another account, retired generation, study, changed configuration or unsupported channel. Unknown-response retry repeats the exact body/key; it never advances the acknowledgment timestamp or silently acknowledges replacement instructions. The service may return a historic accepted same-key receipt without restoring current authority; every subsequent Start remains subject to current admission. A new protocol requires explicit new presentation/confirmation and, where the check context is frozen to an older version, a new check.

The implementation may additionally declare signed `participant_protocol_sha256` and `instruction_receipt_id` fields across the service, generated schema, native client and reader parser. Those fields must exactly match immutable server scope. Existing strict reader binaries that do not recognize the expanded token remain incompatible and fail closed; stripping signed fields or silently normalizing them into the earlier envelope is forbidden. A coordinated parser/provisioning update is distinct from backwards compatibility.

Instructions may state posture/rest/activity and permitted whole-system connection choices. A participant confirmation records declared compliance only. G-05, measured/signed device state, actual setup identity and evidence of permitted power/charging/cables/isolation remain separate requirements. A checkbox does not prove electrical safety, observed power state or device qualification. When human ECG requires a state verifier the installed adapter cannot supply, capability/start stays refused even if its document and user acknowledgment exist. An explicit bench/simulator scope cannot be relabeled as human-connected acquisition.

Cardiac rest begins after the owned attempt exists. The current protocol chooses a zero-to-3600-second duration; foreground monotonic elapsed time controls when the app offers confirmation. Background/interruption, attempt/workspace replacement or inconsistent wall-clock changes invalidate current preparation and require fresh guidance. Retained UTC rest-start/confirmation values are participant-declared chronology and never establish that physical rest, posture or electrical isolation was observed.

## Reference-laboratory collection flow

1. The participant opens an actual current study and confirms its exact approved consent. Start check freezes the profile/history and selected reference-lab configuration in an owned draft and immutable context.
2. The saliva stage detects `reference_lab_import_v1`, shows the current approved collection method/instructions and complete permitted form, and obtains explicit protocol acknowledgment. It does not require BLE, a reader advertisement or an electronic calibration unrelated to specimen collection.
3. Start collection creates a distinct collection attempt and sample identity before requesting fresh online collection start. A timer or form progress is not evidence of collection or analysis. Cancellation/withdrawal/namespace change stops acceptance immediately.
4. Record sample retains actual collection event time, method/version, status/quality and protocol-permitted saliva/buffer volume, dilution definition/factor, collector/container, supply lot/expiry and bounded handling events. Null reasons are drawn from the exact approved subset of `unknown`, `declined` and `not_applicable`. Required unknowns, inconsistent dilution, expired supplies or missing identity prevent a valid claim, while an explicit reason-bearing invalid disposition preserves actual failure lineage. Negative/impossible quantities or times remain rejected rather than normalized into valid evidence.
5. The API returns an immutable owned collection receipt bound to the started attempt, instruction receipt, full configuration scope, specimen and exact accepted metadata digest. Participants never submit THC values, source-report authority or laboratory-role declarations in this operation. Server derivation decides current acceptance; successful local form validation alone does not.
6. The client displays Sample collected / Laboratory analysis pending, or the exact failed collection disposition. No pending analytical value or impairment result is invented. Feature-only collection can continue when the approved protocol allows it; raw recording consent is separate.
7. The laboratory import route is extended to admit a distinct currently authorized staff actor for the participant-owned draft/sample and verified report. The released staff role must permit that study and import operation; target participant, current generation/consent, collection receipt, method and report must match independently. Source evidence and resulting imports remain participant-owned, while the audit retains staff actor and participant target. The caller's role or generation cannot replace the participant's scope. Measurements retain original collection time and explicit analytical time/qualifiers/basis/units. The participant can refresh the approved returned evidence; refresh cannot fabricate or self-import a report. Delayed results do not become measurements of the import-time physiological state.
8. The customer may save/leave/resume the same pending draft or continue to another supported stage without recollecting. Active/pending laboratory analysis blocks finalization with `LAB_ANALYSIS_PENDING`. Explicit abandonment appends a minimal immutable `collection_abandon` proof binding the original collection and configuration digests; it cancels analytical handoff without changing the actual collected specimen or collection attempt. `POST /v1/sessions/{session_id}/collections/{sample_id}/abandon` requires explicit true confirmation and a bounded `USER_CANCELED`, `PARTICIPANT_DECLINED` or `SPECIMEN_UNAVAILABLE` reason. Status reports `analysis_canceled`, source/import/replay authority refuses, and finalization requires the current minimum-channel scope to permit missing chemistry. A required chemical model input remains absent. Before finalization, a permitted failed collection retry creates a linked new collection/sample attempt and retains the failure. After finalization, another specimen requires a replacement check; same-specimen correction/reanalysis uses the independent companion-revision workflow.

The released laboratory protocol bounds `maximum_collection_submission_delay_seconds` to 1–3600 and `maximum_analysis_delay_seconds` to 1–604800. Service admission distinguishes actual collection, actual analysis and import/receipt times, never replacing an old event with current upload time. Research execution additionally enforces its own frozen acquisition and delivery cutoffs. Pending collection cannot satisfy a required measured chemical input; it does not globally disable independently approved missing-channel model configurations after explicit permissible abandonment. Strict Session 0.1 remains sample-only with empty/null/not-measured analytical fields until genuine import. New collection/instruction metadata belongs to declared typed companion contracts, not unknown legacy fields or asserted quantitative provenance.

Collection is separate from analytical qualification. An accepted collection receipt establishes admitted specimen metadata, not a quantified or validated concentration. Valid sample status does not grant a measured analyte. Any temporary use of reference-lab provenance describes the configured analytical workflow; quantitative reference-lab results still require an actual authorized import receipt. This distinction must be explicit in projection validation and UI.

## Selected digital PPG adapter

The selected hardware is SparkFun SEN-15219, MAX30101 plus MAX32664 sensor hub at its documented I2C address. The official SparkFun Bio Sensor Hub Arduino SDK is pinned to `91575258e5e2c47f0f4b8ec97b651381671f4637`, version 1.1. Actual implementation must use that SDK's documented initialization/BPM mode and explicit provisioned Nano pin mapping. A generic ESP32 ADC, a direct MAX30101-only algorithm or fake heart-rate generator is a different adapter.

The typed protected material pins adapter/extractor/SDK identity, actual hardware/firmware, reset/MFIO/I2C configuration, mode, acquisition/polling/validity bounds and any calibration scope. Initialization and each vendor operation retain original error/status semantics. A freshly started acquisition resets or discards stale buffered sensor output using the documented interface. Only a successfully obtained new FIFO record advances received/valid/invalid sample counts. An empty FIFO, duplicate/replayed record, malformed/short I2C response or elapsed poll does not create a sample or reuse an earlier bpm as current.

The driver preserves vendor finger detection, confidence and approved derived summary values with names/units and bounded provenance. Underlying raw/processed sequences are persisted only under a separately implemented approved recording purpose/codec; feature-only capture discards them after extraction. Confidence remains a vendor acquisition-quality score, never a calibrated correctness or impairment probability. A valid heart-rate summary needs the exact approved mode, accepted finger/status/confidence/range rules, enough actual new records and a named finite aggregation. Failure gives null heart rate and explicit reasons. Unknown native cadence, FIFO-drop counts or vendor timestamps remain unknown with reasons; host polling cadence must not be called an observed sensor sampling rate. PPG never fills ECG RMSSD, SpO2, chemical concentration or inference fields simply because another vendor output exists.

The final normalized projection/signature binds the existing protected device key, current authenticated peer/origin, actual boot, single-use signed server grant, channel, configuration material/envelope, context, instruction receipt and bounded acquisition times. The existing server-start full configuration digest covers the protocol; no alternate phone key or advertisement establishes authority. Samples are acquired locally without per-sample network calls. Raw retention requires an implemented approved codec and separate current purpose permission; feature-only summaries do not retain unsolicited streams.

Start, read, reset, stop, signature, RX and notify preserve the existing origin mutex and secure-link admission. Hardware stops at the conservative signed deadline before TX pressure can delay termination. Cancel, contact/quality failure, disconnect, reboot, stale callback and connection replacement cannot restart or settle a previous acquisition under a new origin. The standard build may compile an intentionally unavailable protected runtime, while the security-enabled SDK build must actually compile the selected driver and pinned dependencies. Neither is a flashed or validated sensing system.

## Restricted cardiac server interval authority

The current signed ADC and selected digital PPG adapters retain unqualified server-wall/host-receive timing flags. An independently approved hardware record alone therefore cannot complete the positive HR model path. The new exception is explicit and narrow: model `required_channels` is exactly `cardiac_hr`, the actual artifact has exactly `cardiac.heart_rate_bpm`, and `cardiac_timing_policy` specifies `server_issue_to_attestation_receipt_v1`, exact `calibration_id`, finite `max_interval_ms` and `allow_baseline_delta`. Other cardiac/ECG/response/chemical predictors do not inherit this authority.

A separately submitted/reviewed/released `cardiac_server_interval` calibration binds exact protected device/key, hardware, firmware, modality, adapter/extractor, configuration registry ID/version/full submitted digest, the same method/maximum interval and externally qualified `follows_current_signed_grant` behavior. Its approved maximum interval is 100–120000 ms and finite `server_utc_error_ms` is 0–1000 ms. Configuration and channel qualification must have current `qualified_measurement` purpose. The selected vendor reset/FIFO freshness and host-receive limitations stay explicit; a server clock cannot prove sensor freshness or a clinical assay. Real behavioral calibration/validation must be supplied independently rather than inferred from this software.

The server resolves the immutable authorization's original signed issue and the exact owned signature-verified attestation record's original receipt. Their finite ordered interval is a conservative custody/possible-acquisition bound, not an observed sensor timestamp. Both endpoint UTC-error margins widen the interval; construction and validation use the same outward-rounded bound calculation. Current model width, acquisition and delivery-age comparisons use these independent numerical bounds directly; they never replace null timing, delete flags or rewrite the immutable snapshot/target chronology. Replays do not renew endpoints. Only the adapter's exact known unqualified timing flags are allowed under this exception; contact/range/confidence/drop/unknown flags still refuse.

For the selected SDK, the independently reviewed scope supplies `maximum_monotonic_rate_error_ppm` from 0–10000 and the companion retains the actual device-signed acquisition duration. Its exact rational consistency test is `duration_us × 1000000 ≤ custody_window_us × (1000000 + ppm)` over the unrounded widened service endpoints. Rounded millisecond limits cannot hide a shorter actual interval. ADC evidence retains null signed duration/rate rather than inferring an unsigned transport duration. The bound does not recover sensor onset, FIFO age, actual sampling cadence or absolute device UTC.

Personalized baseline delta requires explicit permission and full independent baseline evidence admission under the same exact device/key/configuration/calibration/adapter tuple, plus the frozen historical age limit. Current proof cannot qualify a missing or unverified baseline. A separately hashed companion in ResearchResult 1.1.0's authority manifest binds original intervals, inputs, released records and original flags; conditional numeric admission, execution, publication, replay and read recheck current authority. An otherwise authorized measurement job may be queued and processed without HR-model authority, producing only its ordinary measurement result; accepting that job grants no numeric authority. Older 0.1 results remain unchanged. No provider receipt, compile, test fixture or approved model substitutes for physical device, timing/behavior or study qualification.

The offline toolkit's earlier unconditional flagged-row refusal would exclude all such original cardiac evidence. Its new mode therefore requires a frozen strict `cardiac_timing_policy`, reviewed source-bundle/custody references and digests, the full unchanged current snapshot and typed authority. Personalized fitting additionally requires the full original baseline snapshot bound by the companion, the same exact calibration/device/configuration tuple and the prespecified historical age limit. The toolkit derives only original current HR or the exact current-minus-baseline delta, independently recomputes conservative bounds at the row information cutoff, and preserves original quality flags. An arbitrary prior row cannot stand in for missing baseline evidence.

The explicit `cardiac_hr_only` artifact/report branch retains train-only preprocessing/fitting, locked leakage-resistant held-out/later-session partitions, invalid/abstaining/all-row denominators, endpoint and complete six-dimension strata. It does not fabricate chemistry/app/ECG ablations or claim multimodal superiority. The original mode retains all four matched ablations. EVAL-002 is modified explicitly for this separate frozen mode; archive requires its original capability first. Structural JSON/hash checks establish reproducible consistency only: actual retained source signatures, registry/calibration approval and independently reviewed custody still require separate trusted verification. Editable references or a test cohort do not supply that evidence.

## Verification and limits

Required software evidence includes typed positive/negative schema cases; actual API owned draft → instruction receipt → fresh collection → immutable receipt → pending lab → authorized import/finalize/companion handoff; native shared client/forms plus browser components; lost-response/config-change/withdrawal/account-switch races; actual-used SDK adapter with fake I2C/FIFO malformed/empty/late/reset fixtures; strict portable/threaded driver tests; both actual stock/protected firmware builds; cross-language signed completion and current backend validation. Tests with transport/storage doubles remain labeled; real PostgreSQL/LocalStack checks and the exact revision's >80% coverage/ATDD/component/performance/live/health/API/native aggregate remain mandatory.

Actual methods, three independent approvers, study eligibility/consent, physical PPG accuracy/contact/motion/cadence, electrical safety/power observation, real native lifecycle and store/AWS/hosted access are separately observed external gates. No task checkbox, test cohort, source signature or compile artifact closes them.
