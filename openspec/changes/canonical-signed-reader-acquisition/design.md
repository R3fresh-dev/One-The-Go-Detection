# Implementation contracts

The native BLE adapter keeps the existing bounded framing while admitting `prototype_sensor` only through `otgd_signed_reader_v1`. Server receipts create trust; an advertisement or structurally valid DER never does. Immutable identity and workspace tuples are carried through all asynchronous operations.

The binding domain is `OTGD-BIND-v1\n`. A protected device P256 key signs the exact server challenge JCS. Capture uses an actual32-byte device nonce and physical boot ID. The current owned attempt's server start token signs a strict grant under `OTGD capture grant v1\0`; the domain is22 bytes including NUL and the complete token is base64-carried by normal JSON framing. Reader verification uses a protected provisioned server SPKI, not an SPKI supplied by the token. The token binds full scientific/submitted configuration, context, channel, maximum duration and raw permission.

The shipped actual ADC driver loads only encrypted-NVS provisioned material and never uses test defaults. Only independently approved cardiac/ECG channels are supported by this hardware driver. `analogRead` returns actual ADC counts; contact and observations use actual GPIO/monotonic readings. The bounded versioned extractor computes intervals/features, explicitly invalidating poor contact, saturation, sample gaps or insufficient evidence. Approved ECG reference, offset and gain permit unit conversion; they are not inferred from sensor counts. Absolute timestamps retain an explicitly unqualified signed-server wall anchor. Physical timing/calibration evidence is still required before eligibility.

Connection transitions share an origin gate with signing, hardware start/poll and notify. Cached participant replies are scrubbed on reconnect while old command/hash/origin tombstones remain. Raw data and signing cannot cross into a replacement origin. Sample shutdown precedes TX pressure handling, and the protected approved end guard prevents scheduler quantization from exceeding signed duration. ADC defaults to feature-only and retains no waveform without separate signed recording permission. The bounded ECG codec branch below supports opt-in only when protected approved encoding/capacity and the complete configured sampling budget match; every unsupported raw configuration or channel is refused. The selected vendor PPG adapter remains feature-only without a separately supported raw codec.

The custom ESP-IDF project compiles the actual reader against security-enabled NVS/secure boot/flash encryption using immutable official sources, exact locked Python tool dependencies and explicit private RSA3072 boot-signing material. It invokes no flash/provision/eFuse operation. Generated configuration and actual binaries are checked, and metadata distinguishes compilation from deployment and physical proof.

Portable core tests, actual P256 verification of backend HTTP fixtures, framed native-client negatives, stock board compile and security-enabled SDK compile provide separate evidence. iOS/Android radio, electrical isolation, hardware key secrecy, real sensors, assay vendor integrations and physiological model qualification remain independently gated.

Protected transport additionally requires BLE LE Secure Connections, MITM and bonding. The protected reader namespace contains a unique six-digit `ble_passkey`, supplied offline and displayed on a controlled physical per-device label. There is no default key, log disclosure, Just Works fallback or unattended numeric confirmation. GATT capability/command/CCCD access requires encrypted MITM permissions; actual peer address, connection ID and generation fence RX insertion, authenticated admission and notification effects under the same connection gate. Bond storage uses the encrypted NVS SDK. Three failed authentications deny further associations until operator restart. Actual OS pairing, physical label custody and bond recovery must be qualified separately.

The bounded ECG recording branch accepts only signed non-null record permission and approved protected `raw_sample_limit` in 1..1024 with `raw_encoding=otgd_ecg_samples_v1`; the complete configured sampling budget must fit. Feature-only extraction does not retain samples. Actual observations are retained in bounded RAM during acquisition, then emitted as unchanged individually signed chunks, at most 64 observations per chunk with explicit sequence gaps and measured monotonic microseconds. The app's transport handoff is `OTGD-ECG-SAMPLES-v1\n` followed by canonical UTF8 JCS containing the exact final attestation and unchanged sample chunks. Its byte digest and dimensions are checked before encrypted local retention; there is no phone signature or automatic upload. Server verification against the approved device key remains authoritative.
