## Transaction and authority disposition

[access()](../../../../services/api/otgd/main.py) verifies the bearer signature before SQL checkout. It owns one idle engine connection and binds two separate Sessions to it. The first performs all original database authority checks and commits the rate cost; it closes before the second Session independently verifies the original token again and repeats current journal, identity, recovery, family revocation and account admission. There is no outer `engine.begin()` transaction. Installed SQLAlchemy semantics were independently inspected: an already-active outer transaction would make default Session commits rollback-only and invalidate rate persistence. The implementation avoids that state.

The request-local signature proof is constructed only from verifier output, never HTTP JSON. Phase two receives the original header string. Separate Sessions prevent first-phase ORM identity state from substituting for second-phase authority reads. Generation and consent remain checked downstream; no authority cache, admission skip, pool increase or producer-lease bypass is introduced.

The first rate cost stays durable if downstream admission or a handler is denied. Phase-two writes roll back on errors and cancellation, and nested contexts close each Session before returning the connection. The 429 path retains its original deliberate commit. Ownership ends at `access()` exit: export download/streaming stays outside it, with short independent re-admission transactions before delivery chunks. A second-phase JWKS refresh can hold the checkout while verification completes; source structure alone promises no latency bound.
