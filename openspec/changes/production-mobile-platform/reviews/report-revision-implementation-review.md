**Date:** 2026-10-11. **Specification checkpoint:** `8aa56ce9883aaafeba11b809c94bc406e7ee0a0a` precedes this follow-up implementation. The normative [amendment](../report-revision-contract.md) and its [specification review](report-revision-review.md) remain the acceptance basis.

This ledger records root and independent mobile review findings, the author's source corrections, and focused host evidence. A source or host resolution is not an actual PostgreSQL, S3, mobile operating-system or laboratory acceptance result.

## Implemented boundary

The [report module](../../../../services/api/otgd/report_revisions.py) supplies a purpose-specific finalized-report ticket/completion path, current administrative authorization before mutation replay, immutable report/result companions, separate typed list/detail reads, chain integrity validation, frozen export heads and bounded export records. The original session, capture context, attempts, manifest, snapshot hash, result and target/collection/acquisition timestamps remain unchanged. Report issue/analysis/evaluation times are separate. The result cannot promote an invalid or inconclusive original and always has unavailable inference and null classification/probability/model fields.

The isolated [API integration](../../../../services/api/otgd/main.py) rejects administrative-purpose artifacts on both phases of generic capture completion, records exact revision heads at export acceptance, and includes the new router. The [worker](../../../../services/api/otgd/worker.py) creates separately bounded companion files and a hash-indexed check reference. Existing generation deletion removes both new record kinds and cleans their original tracked artifact namespace.
