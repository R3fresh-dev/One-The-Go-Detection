# Administrative report revision amendment — adversarial review ledger

**Date:** 2026-10-11. **Reviewed artifact:** [report-revision-contract.md](../report-revision-contract.md). **Review stage:** specification before follow-up code. Source/runtime implementation is not yet claimed.

| Finding | Severity | Counterexample | Required correction | Specification resolution | Implementation status |
|---|---|---|---|---|---|
| RREV-001 | High | Reusing a draft-only generic artifact completion path for a finalized report either fails the intended workflow or invites a broad relaxation of original human-capture gates. A cleanup-claimed report could otherwise be resurrected at completion. | Pin an administrative report purpose at ticket issue; use a separate completion route with current finalized-check/operator/policy authorization before I/O and again under a refreshed commit lock; keep generic capture restrictions. | §§2–3 now define the purpose-specific route, exact server-owned purpose, generic-route rejection, two authorization phases, immutable metadata recheck and retired-artifact refusal. | Pending code and two-phase/revocation tests. |
| RREV-002 | Medium | A base inconclusive result acquires a valid chemistry correction and is silently presented as measurement-only, hiding the original unresolved assessment. | Preserve base inconclusive as well as base invalid; a newly invalid report can make the companion invalid but valid chemistry cannot repair unrelated evidence. | §5 now defines the exact invalid/inconclusive/measurement-only precedence with null inference fields. | Pending code and state-preservation tests. |
| RREV-003 | High | Existing generic mutation helpers return a same-key stored response before the handler checks the operator role or study consent. Revoked administrative authority can therefore replay a health-bearing mutation response as though authorized. | Check current owner/generation/recent auth/operator/study/consent/report authority before every administrative mutation replay; retained ordinary read is a distinct authorized route. | §6 explicitly requires current administrative checks before idempotency replay for revision, ticket and completion paths, with no special retained mutation-response bypass. | Pending code and revoked-role/consent replay tests. |
| RREV-004 | Medium | Undefined future-time tolerance and unbounded operator/method registry fields lead to divergent validators or unbounded work. | Freeze numerical clock and registry bounds; reject missing/malformed records without inventing method authority. | §§4–5 fix a 60-second future allowance; role/study/method/calibration/instrument list, string and expiry bounds are explicit. | Pending code and boundary/malformed-registry tests. |
| RREV-005 | Medium | Canonical `not_measured` requires null analytical identities/time, but requiring a performed-method lookup for every changed analyte makes an authorized report withdrawal impossible or encourages fabricated method metadata. | Permit explicit authorized nonmeasurement with canonical nulls, retaining operator/study/consent/report authorization; require approved analytical metadata for every other replacement. | §§3–4 define the exact nonmeasurement exception and refuse analytical claims for it. The approval descriptor pins only actually used analytical method mappings. | Pending null-withdrawal, approval and UI tests. |
| RREV-006 | High | Embedding 20 maximum-sized companions in one check object creates a roughly 10 MiB structured record and defeats the existing 512 KiB bound. A worker retry could also pick up a report added after export acceptance. | Use separately named bounded companion records, an exact bounded check index and manifest hash references; freeze each selected report head at export acceptance and validate the complete indexed chain. | §7 fixes `report-revisions/{session_uuid}/{revision_uuid}.json`, 512 KiB per companion, a 16 KiB index, exact hash/identity references and parser refusal rules. Existing archive totals/count bounds remain. Exact export heads are persisted at acceptance; missing old-job heads mean no revisions. | Pending separate-record archive, malicious-index, size-limit and frozen-head retry tests. |
