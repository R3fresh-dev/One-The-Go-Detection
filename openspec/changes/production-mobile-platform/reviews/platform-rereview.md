## Final closure details verified

1. **Idempotency lifetime:** Shared §4 now states retention of minimal key/digest/operation-reference metadata through the entire writable generation. Cleanup cannot turn a late retry into a new mutation. Sensitive response bodies disappear when the underlying authorized record disappears; retired-generation handling retains only policy-permitted metadata/receipts. An expired export replay returns the original job's expired disposition. A stale generation remains denied before any data-bearing replay.
2. **Recovery of non-deletion revocation:** Shared §3 and Platform §7 now address post-backup logout/withdrawal rollback explicitly. Before reopening, recovery writes and verifies an independent RecoveryActivation record, applies its monotonic authentication cutoff, and requires signed auth_time at/after that cutoff. Refreshing an old family cannot bypass the check using a newer iat. The next restore reads the maximum retained independent cutoff. Recovered study, consent-derived capture, and device qualification/binding authority remain suspended until independent current records reconcile them; absent evidence leaves them unavailable. Freshly authenticated history/privacy access remains separately governed.

## Additional adversarial checks performed

### Conditional upload and late-arrival boundary

The first correction bound each upload's byte length but allowed the signed URL to be reused to create many versions. A storage reservation for one object did not cover that amplification. The revised ticket signs Content-Length, Content-Type, the base64 SHA-256 checksum header, and If-None-Match:*, plus explicitly required encryption headers. The public host is signed and never rewritten. Bucket policy enforces the condition. Client multipart is absent from this release.

An S3 412 is an existing-object reconciliation path, not permission to mint an unrestricted overwrite. Cleanup preserves the current object until at least ticket expiry plus the engineering margin so it does not reopen the still-valid conditional-write opportunity. The margin is not a claimed maximum transfer duration. Repeated quarantine reconciliation, retained references/accounting, and honest pending/failed cleanup state cover known outstanding and detected late arrivals. These conditions require LocalStack and real AWS evidence before upload compatibility is claimed. Primary references: [S3 conditional writes](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html), [policy enforcement](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes-enforce.html), and [presigned URL behavior](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html).

### Restore before the account existed

The re-review extended the journal identity requirement from account deletion to all-data deletion. Without that extension, a backup predating account creation could contain neither the old opaque account UUID nor its issuer/subject binding. A returning token could receive a different UUID at generation 1 and submit an old generation-1 operation. Platform §7 now requires a keyed subject-reference lookup, original account reference, maximum generation, and appropriate blocked/new-workspace state for both scopes. A missing key or ambiguous restored binding fails closed. The HMAC is a protected pseudonym, not an assertion of anonymity or permission to retain health content.

### Native evidence and platform coupling

The reaction feature freezes the pre-code [configuration](../fixtures/reaction-task-config-v1.json), [literal golden data](../fixtures/reaction-task-golden-v1.json), and [digest/comparison conventions](../fixtures/README.md). The platform review checked the 66-trial/1,024-input bound, 512-KiB native-completion limit, full companion-evidence retention, namespace/run/attempt identity, one terminal transition, immediate native stop before navigation, and null features after invalidation. Native timestamp resolution is not physical timing qualification. The actual guest task maps to prototype_sensor and stays local rather than being relabeled simulated or uploading through a synthetic account. Domain/timing adjudication and physical validation remain separate; this review does not duplicate their evidence claims.

## Evidence that remains required after implementation

The specification checkpoint can now authorize implementation against these contracts. It does not authorize claiming the following as already passed:

- **Contracts and concurrency:** typed/generated mobile/API route agreement, exact canonical hashing, stale ETag/generation denial, deletion/logout receipt exceptions, ownership, revocation, and late-response races.
- **LocalStack:** exact pinned image, actual versioned S3 conditional upload/checksum/size behavior, actual SQS delivery/lease/DLQ behavior, persisted results, authenticated export, and bootstrap repeated without data reset. Missing Docker/license/token remains unexecuted.
- **Workers and recovery:** the kill/lease/fence matrix, committed-output-before-ack order, recovery requeue, poisoned jobs/replay, both-scope journal acknowledgment loss, restore predating account creation, unknown journal interval, and late quarantine cleanup.
- **QA AWS:** real task-role/bucket-policy enforcement, image/secret/JWKS/network paths, hosted sign-in, actual RDS connection budget, migration failure/rollout/rotation/drain, backup restoration, and alarm delivery.
- **Cost and deployment:** dated us-east-2 resource/usage estimate or recorded region override, owner-set budget/destinations, named operator, residual-cost teardown, and deployment manifest. No paid infrastructure or external notification was created by this review.
- **Mobile and science:** Android/iOS native builds and device/simulator/accessibility rows, physical display/touch calibration, assay performance, optical configuration, human-connected ECG review, real study permission, and model qualification. Current inference remains unavailable regardless of code/test completion.

Implementation and release ledgers must preserve these distinctions. A no-op substitute, in-memory AWS mock, generated template, or JavaScript bundle is not interchangeable with the named deployment/device evidence.
