The `apps/mobile/modules/eye-capture` Expo module supplies `optical_roi_v1` using Camera2 on Android and AVFoundation on iOS. It accepts the exact canonical bytes and SHA-256 of an online, released `ExecutableOpticalMaterial`; the app must first obtain and start its owned acquisition authorization. Permission, phone model, OS version, native build, exact camera/lens/format, reviewed frame rate, ROI, output rotation and extractor settings must match. Camera access starts only after the participant explicitly starts capture and grants camera permission. A positioning preview does not authorize recording.

The camera inventory exposes device identifiers, formats and supported frame-rate ranges for an operator to review. These identifiers and all numerical examples in the checked-in goldens are fictional fixtures, not approved defaults. This module never supplies a human-study approval, calibration or clinical model.

Frames remain bounded to 300, at most ten seconds and at most 128×128 sampled ROI pixels per frame. Android matches exposure/focus CaptureResult metadata to the image sensor timestamp; its sensor clock must report REALTIME. iOS reports the AVFoundation sample timestamp and device exposure/focus state observed at the callback. The latter is explicitly `device_state_at_callback`, with `EXPOSURE_NOT_FRAME_MATCHED`; it is not represented as per-frame exposure attestation. `camera.width/height` identifies the approved source format, which Android checks against the delivered source image. `output_width/height` identifies the processed coordinate extent after the reviewed rotation. Android rotates coordinates during ROI sampling; iOS rotates its delivered output plane through the camera connection and checks that plane against the expected output extent. Neither operation establishes physical sensor orientation. A bounded three-frame callback queue fails invalid on overflow. Timestamp regression, gaps, excessive dispatch delay, unsupported format/focus/frame rate, lost permission, interruption, backgrounding, hidden/detached view, layout change, changed workspace and camera errors stop capture. Callbacks carry their originating generation; Android owns camera handles in a per-run lease on a process-lived callback executor so a late open cannot attach to a replacement capture.

Each frame retains `sensitivity_iso`, which remains null when unavailable, and a platform-specific `autoexposure_state`. Android joins images and CaptureResults in either arrival order using the exact sensor timestamp, with at most three pending images and sixteen metadata records; a missing match expires within the reviewed frame-gap bound. iOS labels ISO/exposure/AE observations as callback state. Unknown or searching/adjusting AE cannot produce accepted segmentation. Neither platform invents a sensor gain or substitutes the last observed result for an unmatched frame. Each sampled ROI also carries the SHA-256 of its actual luminance bytes.

A failure before the first accepted camera frame emits an invalid terminal with `native_result:null` and `raw_recording:null`, preserving the originating run, workspace, authorization and reason. Acquisition timestamps remain absent; the app preserves its separate arming timestamp. Android UTC wall timestamps use an API 24-compatible formatter, while frame timing retains its monotonic camera clock.

The data-only `otgd-dark-component-v1` extractor samples luminance at approved ROI cell centers, applies a reviewed dark threshold, and finds four-connected components. It rejects edge components, unapproved area, low roundness/contrast, and multiple plausible components. Its accepted output is a descriptive normalized dark-component diameter and center. Synthetic pixels verify arithmetic, not anatomical pupil identity. Scientific use requires independent segmentation/device qualification.

Two conditional modes are implemented:

- `passive_ambient_no_modulation` changes neither screen brightness nor illumination. It has no light-response latency or relative constriction estimate.
- `reviewed_display_step` requires explicit reviewed gray levels, display brightness, onset, duration and response extraction windows. The native renderer records Choreographer submission or CADisplayLink target time, then restores the original brightness on settlement or interruption. Requested gray level and brightness are device settings, not measured luminance or retinal irradiance. The callback-derived response estimate is separate from physical light onset. `latency_ms` and `relative_constriction` in the scientific projection stay null until separate physical/anatomical response qualification exists. The callback-relative change remains explicitly descriptive engineering metadata.

Normalized geometry keeps `baseline_diameter_mm` null. Millimeter conversion requires the exact independently released optical geometry calibration, including phone/OS/build, camera/lens/format, output rotation, ROI sample dimensions, extractor and reviewed pixel-to-mm bounds/uncertainty. A component outside its calibrated pixel range produces a null millimeter feature. No conversion is guessed from screen size or distance. The API independently recomputes scalar features and validates the admitted tuple. Native events always report `physical_onset_verified:false` and `model_eligible:false`; an independent model admission policy must decide whether an approved diameter-only model has sufficient authority. Timing-dependent models remain unavailable without their own physical qualification.

Optional raw recording is separate from measurement and defaults off. Only a fresh start permission with `record:true` enables a RAM-only sequence of approved ROI luminance frames. No plaintext file or full-face frame is written. A successful completion hands bounded base64 chunks to the app for its SQLCipher BLOB commit; each chunk decodes to at most 196608 bytes. `releaseRaw(runId, sha256)` removes the native handoff after the commit or abort. An unacknowledged handoff expires after 30 seconds; idle privacy/workspace/background/detach transitions remove cached native media and terminal state. Saving locally does not authorize upload. The app separately checks the current `upload` permission, policy and revocation fence before an explicit raw upload; the API applies the immutable retention lifecycle.

The raw format is `application/octet-stream`, named `OTGD-EYE-ROI-v1`. It is an ROI frame sequence, not an MP4. Its 16-byte ASCII magic is `OTGD-EYE-ROI-v1\n`, followed by little-endian u16 width, u16 height and u32 frame count. Each frame contains little-endian f64 native timestamp in milliseconds, u32 sequence, and width×height luminance bytes. Sequences start at zero and timestamps increase strictly. The codec contains no subject identity, consent, access token or network URL; the encrypted app metadata binds it to its owned acquisition.

The local encrypted commit checks each decoded frame against `roi_luma_sha256`. Server completion reads the exact admitted S3 version and independently verifies codec dimensions, count, sequence, timestamps and pixel digests against the owned accepted native frame ledger. It reruns the extractor on those pixels and compares segmentation statistics, while preserving explicit invalid camera-metadata reasons. A durable owned `raw_verification` receipt binds the object version/digest, attempt, complete released configuration and accepted native evidence digest; a hash-only upload or manually marked verified row cannot authorize raw export. This software linkage does not attest anatomical identity or physical sensor authenticity.
