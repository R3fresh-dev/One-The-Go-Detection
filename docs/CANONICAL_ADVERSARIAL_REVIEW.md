## Scope and source of evidence

The canonical application consists of `services/api/otgd`, `apps/mobile`, `infra`, `infra/local/compose.yml`, `deploy/platform.py` and the shared scientific/application contracts. The review inspected authentication, consent, acquisition authority, artifact/export/deletion handling, worker fencing, native build regressions, deployment admission, CI enforcement and customer consent behavior.

The separate `backend/`, `mobile/`, `web/`, root `compose.yaml` and legacy CloudFormation deployment helpers are preserved local drafts, outside the canonical staged application. Their tests, registry endpoints, browser previews and deployment features do not establish that the committed canonical application implements those features. Historical local review drafts contain legacy-path statements and counts and are excluded from this change; use this report and the current canonical gate evidence when assessing the proposed application.

Source inspection and focused tests were distinguished from live dependencies, actual operating-system builds, physical-device qualification and AWS acceptance. Fictional approvals, mocked AWS calls and simulator artifacts were never accepted as real study/device/model approval.

## Regressions addressed during this review

| Finding | Current resolution and review limit |
|---|---|
| Replacing the HMAC secret bytes while retaining the same key label admitted a deleted subject as a fresh active account | Independently reproduced against the prior canonical revision. `identity_keys.py` now binds the label to the full secret fingerprint in migration-owned `SystemState`; API admission/readiness and migration reject missing or changed provenance. Rotation remains deliberately unsupported. Regression cases cover the same-label/different-secret bypass. |
| A completed account deletion prevented its owner from retrieving the minimal deletion receipt | The receipt-only authentication path permits the narrowly scoped owner receipt while ordinary data/export access remains denied. Foreign receipts remain inaccessible. |
| An existing consent prevented a later approved document from being accepted | Consent now preserves historical immutable receipt rows and a separate current pointer. The exact current invitation ID, document version and digest are checked, including in qualification. A lost-response replay preserves the original receipt and cannot roll the pointer backward. |
| A changed document could reactivate a withdrawn invitation | The server rejects reconsent under the same withdrawn invitation, even after a document change. A newly issued invitation is required. The UI assesses the exact tuple, shows updated-document consent when appropriate and keys the card by that tuple so the old acknowledgment does not carry forward. |
| Operator retirement could change a referenced registry row during acceptance | Referenced registry rows use a transaction-held PostgreSQL share lock. The backend owner added an actual PostgreSQL retirement/concurrent-consent check; SQLite cannot establish this locking property. |
| Old refresh promises or sign-out replies could affect a replacement account | Mobile refresh single-flight is scoped to the authentication epoch; an old finalizer cannot clear a replacement refresh promise. Sign-out checks its originating flow after awaits, including before provider logout and before UI changes. |

The original API deadline spans token retrieval, transport, body parsing and the one 401 retry; export downloads have a separate bounded deadline. |
| A late consent reply could revive a locally withdrawn queued intent | Queue guards now run both before enqueueing a receipt commit and inside its serialized callback. Success and error paths preserve blocked/conflict/quarantined/finished barriers. A deferred-commit regression exercises withdrawal publishing between enqueue and callback execution. |
| Android nullable scientific fields failed the actual Expo native build | The native event dispatcher preserves `Map<String, Any?>`; no null-dropping cast was introduced. Android fixture tests use APIs available on the Android JSON classpath, and the actual Expo/RN serialization test has a test-only React Android dependency. | Logout failed after all-data deletion moved the account to a locked generation state | The own-family logout route permits its minimal revocation operation in deleting/deleted/awaiting-acknowledgment states and with its retained originating generation. Focused regression checks pass; the rebuilt live application journey must verify the fix. |
| Per-request schema rebuilding inflated the concurrent workflow cost | Only immutable source schema/reference compilation is cached, with bounded cache inventories and serialized cold compilation. ## Requested software still outstanding

These are implementation gaps, not requests to purchase credentials or obtain scientific approval. They remain open even if the CI milestone passes.

| ID and priority | Finding, concrete impact and required implementation |
|---|---|
| CAN-01 — blocks a usable authorized research release | **Operator registries and customer capabilities are incomplete.** `domain.registry()` reads independently provisioned generic rows, but there is no canonical operator workflow implementing the full study/consent/device/calibration/model submission, independent review, release, expiry and retirement lifecycle requested by the user. The read-only runtime grants are appropriate; tests inserting `Registry` rows are not an operator provisioning implementation. `main.capabilities()` returns every channel unavailable with the same constant reason, irrespective of approved registry/consent state. `model_get()` serves the fixed unvalidated manifest. Implement audited operator administration with immutable versions and separation of duties, then compute each customer capability independently from current authority/configuration/device/calibration/consent evidence. Empty or unqualified deployments must remain closed. |
| CAN-02 — blocks retaining real participant raw data | **Optional raw consent and approved retention deadlines are absent.** The canonical consent DTO/UI records one study acknowledgment, not the separately optional raw-upload choices in `ONBOARDING-CONSENT-002`. `artifact_upload()` checks the operator configuration's `raw_retention_approved` flag without a separate participant choice. Its `Artifact.expires = now() + 300` is an upload-ticket deadline. `worker.cleanup_once()` selects quarantine/cleanup/purged artifacts, excluding verified raw objects. Verified eye videos, ECG waveforms and source laboratory reports therefore have no study retention-expiry scheduler; administrative report uploads have the same retention gap. Implement immutable participant choices, an independently approved bounded retention policy, a distinct retained-until deadline and version-aware recurring cleanup. Test expiry, policy withdrawal/change, already admitted uploads and late arrival. Do not enable real raw retention before this is implemented. |
| CAN-03 — blocks the requested deployed web experience | **Canonical AWS web hosting, UI DNS registration and their deployment are missing.** `infra/lib/platform-stack.ts` provisions the API/worker/database/identity and data buckets, but no canonical private static-web origin/CDN, web asset publication or signed-release binding for the Expo web UI. The preserved local-draft Route53 CNAME helper is excluded from this change and cannot supply an application target that has not been deployed. Implement HTTPS web hosting, exact browser callbacks/CORS, reviewed headers and asset publication, then register and verify the owned UI domain against that deployed target. |
| CAN-04 — blocks the requested one-command deployment interface | **Canonical separate QA/prod one-shot wrappers are missing.** The preserved local-draft `scripts/deploy_qa.py` and `scripts/deploy_prod.py` import the draft `scripts/deployment.py`, which operates on the historical CloudFormation/backend path; they are excluded from this canonical change. The canonical `deploy/platform.py` exposes separate registry/build/deploy-stopped/bootstrap/migrate/activate operations. Implement canonical QA and production orchestration that performs preflight, infrastructure/security provisioning, immutable code/web publication, stopped maintenance, activation and bounded verification in one explicit run. Preserve QA/prod account separation, signed evidence, resumable failure receipts and fail-closed activation. Document each argument, required permission, cost/resource scope, retry and partial-failure behavior. Do not advertise the local legacy wrappers as deploying `services/api`/`apps/mobile`. |
| CAN-05 — blocks independently verified recovery admission | **Runtime restore admission remains anchored in the restored database.** `auth.authenticate()` and `/health/ready` inspect database `SystemState.recovery`; the check is conditional on `recovery_required`, which defaults false. The restore CLI writes an independent journal activation record and a verified database state, and the reviewed snapshot path enables the gate, but runtime admission does not independently load and verify the retained activation anchor before trusting restored subject/generation state. A restored stale database with a false gate or stale verification state is therefore not independently detected by admission. Implement an independently retained, source/account/environment/recovery-point-bound activation authority that is verified before subject creation/readiness, and fail closed on missing, stale or unknown journal/key inventory. Exercise restoration from before an accepted deletion and reject resurrected subjects even when the restored database says it is active. |
| CAN-06 — local engineering hardening remains | **The fictional local issuer is not a production-equivalent identity service.** Existing signing-key reads follow filesystem links and do not verify regular-file type, private mode, key algorithm or bounded size. Refresh rotation rejects a consumed token but does not revoke its family on reuse, and each rotation extends the refresh deadline another thirty days. Expired authorization/code/refresh records have no bounded cleanup; chooser requests lack browser-session/Origin binding. Local account deletion does not disable/delete the fictional identity at the issuer. Keep this issuer local and fictional; implement these protections before treating its behavior as an identity parity test. Cognito production authentication does not automatically make the local implementation complete. |
| CAN-07 — documentation and distribution wiring remain | **Hosted iOS preview wiring and remaining setup claims need reconciliation.** Preserved local drafts contain legacy registry/full-gate statements and old native failure descriptions; they are not committed canonical evidence. The local-draft `ios-browser-preview.yml` builds `mobile/` and is excluded from this change; the canonical simulator artifact comes from `apps/mobile` in `native-build.yml`. Implement hosted preview using the canonical artifact and demonstrate an authenticated hosted simulator session. Update canonical setup instructions that still say a paid LocalStack token is mandatory: the current default is the pinned community release; the licensed override is optional. |

CAN-01 and CAN-02 are especially material to the user's requested real-device authorized research platform. Keeping every channel unavailable is a safe deployment default, but it is not implementation of the approval workflows or usable qualified acquisition experience. The verified-raw expiry work was explicitly deferred from the present CI milestone; it must remain open in the feature/spec tracking.

The ECS worker progress-health configuration is now implemented and source-reviewed. Cloud operational acceptance must still exercise unhealthy-worker replacement and the metrics sidecar's failure behavior in AWS; neither synthesis nor local healthy-container checks establish those runtime outcomes.
