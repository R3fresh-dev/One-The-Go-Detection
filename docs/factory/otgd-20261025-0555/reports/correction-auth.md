## Corrected admission

`app.config.ts` independently compiles `EXPO_PUBLIC_OAUTH_ORIGIN` and `EXPO_PUBLIC_OAUTH_WEB_CALLBACK_URI`, alongside issuer/client/native callback. The supported bare endpoints are exactly `/oauth2/authorize`, `/oauth2/token`, `/oauth2/revoke` and `/logout` on that hosted origin. Local/test defaults are the explicit canonical local fixture values. QA/prod have no hosted-origin or web-callback fallback; missing pins fail closed. Issuer is never used to infer the hosted domain. Native callback derives from the environment's fixed app scheme; browser callback is the exact admitted web root.

The public build validator lives in `oauth-build-policy.js` with a typed declaration because the actual Expo configuration loader transpiles the config entry but does not resolve transitive TypeScript helper imports. The runtime TypeScript `src/core/oauthPolicy.ts` wraps that same validator and supplies central metadata/callback/logout admission. This avoids separate conflicting build and runtime policies.

Admission rejects foreign host/origin, unexpected protocol or port, userinfo, altered or encoded path, preexisting query/fragment, changed/duplicate/missing callbacks, wrong issuer/client, and missing independent build pins. Authorization/token paths are required. Optional revocation/logout fields may be absent, preserving the existing optional contract; when present they must equal their supported exact targets. The backend wire schema is unchanged.

`parseAppConfig` validates metadata against compiled pins and returns an independent admitted auth snapshot. `AuthManager` validates before authorization/browser launch, authorization-code exchange, commit/persistence, restored-session adoption, access/refresh, captured revocation and generated/provider logout. Snapshots prevent caller mutation while a popup or old-family operation is pending from retargeting credential traffic. Captured revocation rechecks the admitted snapshot at execution; generated logout accepts only its fixed endpoint with the exact compiled client/callback query. PKCE S256, cryptographic state, callback one-use/expiry and mismatch guards remain; API-before-provider logout, immediate local credential removal and captured-old-family/replacement-login fencing are unchanged. No runtime metadata overrides a compiled destination.
