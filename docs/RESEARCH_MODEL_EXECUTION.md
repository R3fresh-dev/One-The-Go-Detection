# Governed research model execution

The authorized research release implements a conditional model path. It ships
no human model, endpoint validation, cohort or study approval. Fictional fixtures
exercise arithmetic, lifecycle admission, HTTP/native evidence, withdrawal and
commit races; their reports are engineering evidence.

The original measurement-only implementation is extended to the P2 research
behavior already described by FULL_SPEC MOD-010 and ADR-013. This is an explicit
scope amendment to satisfy the requested authorized research platform. Results
remain measurements until all real study, model, acquisition, method, timing,
calibration and consent dependencies are independently released.

## Prepare and approve a model

1. Obtain the actual approved endpoint, population, dataset, protocol and locked
   statistical analysis plan. The [training and evaluation toolkit](MODEL_TRAINING_AND_EVALUATION.md)
   produces bounded data-only artifact and reproducible evidence from supplied
   data. Its output alone never grants approval.
2. Use the exact immutable artifact bytes, at most 65,536 bytes. Upload them to
   the environment's private artifact bucket under `models/`. Preserve its
   actual non-null S3 version ID, byte count and SHA-256 in `artifact_ref`.
3. Prepare the complete model submission against
   [the operator schemas](../contracts/operator). Bind the evaluation report,
   quality, co-use and exact assay compatibility policies to the scientific
   manifest. Thresholds and uncertainty policy are fixed before confirmatory
   evaluation. Personalized models require an explicit maximum baseline age of
   at most 30 days. Required task inputs need separate native timing calibration.
4. Independently submit, review and release the exact model content through
   [operator administration](OPERATOR_REGISTRY.md). Probability calibration and
   each required acquisition configuration have their own reviewed releases.
   Do not load executable models, pickle, arbitrary feature expressions or a
   demonstration fixture as an approved artifact.
5. Link the model ID from the approved study, obtain current participant consent,
   and collect through the exact supported calibrated device/phone and protocol.

## Execution and result behavior

The worker checks current authority before leasing a nonprivacy job, before
computation and before commit. Model execution resolves current notice, account
generation, study membership, consent document, independently released version
and policies, frozen context, selected attempts, methods, configuration and
device bindings. Independent recovery admission and per-study reapproval also
apply after restore. Unsupported, stale or mismatched authority produces no
research score; revocation during calculation cannot commit a stale estimate.

Features use finite approved values. Missing or censored analytes are never
converted to zero. Profile predictors precede the historical target time.
Reaction timing uses the externally qualified phone/OS/build/clock/input/display
tuple and its approved bias. A personalized baseline must be owned in the same
study and data generation, completed before the target, within its age bound and
independently pass current acquisition qualification. All input evidence remains
unchanged; feature transformation is separate and hashed.

Camera acquisition has a separate geometry-only path. The server recomputes
optical scalars from the bounded native ledger and checks the exact released
camera/ROI/extractor/phone configuration, its qualified-measurement evidence and
optical geometry calibration. That authority permits a diameter-only model using
`eyes.baseline_diameter_mm`; it does not qualify latency or relative constriction.
The original physical-onset uncertainty flags remain visible. Unknown quality
failures still refuse admission, and a personalized baseline must use the same
current geometry release. Geometry retirement is checked again before commit.

The uncertainty policy runs before classification. An abstaining result has
null probability, classification and threshold. An admitted result identifies
its research endpoint, population, model version, calibration and threshold.
Result `1.1.0` includes canonical snapshot, context, evidence, baseline, feature,
artifact, evaluation and authority digests. The mobile client checks those links
before presenting research results. Legacy `0.1.0` results retain their existing
measurement semantics and cannot be relabeled as research estimates.

Digest consistency is not scientific approval. Actual validated cohort evidence,
phone/camera/reader qualification and physical acquisition remain release
requirements, separately from the automated software checks.
